== v0.5.8 — 2026-06-01

=== Ajouté

* **OutputIntent + espace de couleurs ICCBased (première étape de J1
  dans la trajectoire ISO PDF).** Nouveau module `PDF::OutputIntent`
  qui permet à un document de déclarer une condition de sortie
  calibrée — prérequis pour la conformance PDF/A-2b / PDF/A-3.
+
[source,crystal]
----
pdf.output_intent = PDF::OutputIntent.srgb     # RGB par défaut
pdf.output_intent = PDF::OutputIntent.fogra39  # CMYK offset européen
----
+
Les intents par défaut référencent deux profils ICC embarqués dans
`src/pdf/data/icc/` :
+
--
** **sRGB v4 ICC preference** (60 Ko) — domaine public, depuis le
   registre de l'International Color Consortium.
** **Coated FOGRA39 / ISOcoated_v2_eci** (1,7 Mo) — libre d'usage
   selon les conditions ECI ; attribution conservée dans
   `src/pdf/data/icc/LICENSE.adoc`.
--

* **`PDF::ColorSpaces::ICCBased`** — première entrée concrète du
  namespace `ColorSpaces`. Détecte automatiquement le nombre de
  composantes (1 Gray, 3 RGB, 4 CMYK) depuis l'en-tête ICC. Factories
  `.srgb_v4`, `.fogra39`, `.from_file(path)`.

=== Modifié

* `PDF::Document#output_intent=` est le setter public. Lorsqu'il est
  défini, `Document#finalize!` écrit `/OutputIntents [...]` dans le
  catalog, ainsi qu'un dict `OutputIntent` indirect dont le
  `/DestOutputProfile` pointe sur un stream comprimé Flate portant
  les octets ICC.
* Le poids du shard augmente d'environ 1,8 Mo pour inclure les deux
  profils ICC. C'est le compromis assumé dans `doc/RATIONALE.adoc`
  (point ouvert n°1, tranché le 2026-06-01) afin de garder les PDF
  générés self-contained sans accès à un fichier externe au runtime.

== v0.5.7 — 2026-06-01

=== Ajouté

* **Support AcroForm interactif (J0 de la trajectoire ISO PDF).**
  Nouveau module `PDF::AcroForm` qui produit des formulaires
  remplissables dans Acrobat Reader, Preview macOS, Firefox PDF.js et
  Chrome. Cinq types de champs dans cette première itération :
+
--
** **Texte** (`/FT /Tx`) — simple ligne et multi-ligne, avec
   `MaxLen`, `Password`, `Multiline`, alignement, valeur par défaut.
** **Case à cocher** (`/FT /Btn` sans flag `Pushbutton`/`Radio`) —
   états `/Yes`/`/Off`, avec état par défaut.
** **Boutons radio** (`/FT /Btn` avec flag `Radio`) — les kids
   partagent `/Parent` et portent chacun un `/AP /N` avec deux Form
   XObjects natifs (anneau vide pour `Off`, anneau + point central
   plein pour la valeur sélectionnée) qui rendent les boutons
   visibles dans tous les visualiseurs. Sans `/AP`, Acrobat et
   Preview n'affichent rien pour les kids ; sans `/Parent`, ils
   ignorent les kids entièrement.
** **Liste déroulante / combo** (`/FT /Ch` avec flag `Combo`) — accepte
   soit `Array(String)` (valeur = libellé) soit `Hash(String, String)`
   (valeur d'export ⇒ libellé affiché), conformément à PDF spec
   § 12.7.4.4.
** **Listbox** (`/FT /Ch` sans flag `Combo`) — choix multi-ligne sans
   menu déroulant.
--
+
DSL :
+
[source,crystal]
----
pdf.acroform do |form|
  form.text_field("nom", page: page, x: 100, y: 700, width: 200, height: 20)
  form.radio_group("genre", page: page, options: ["M", "F"], x: 100, y: 600)
  form.dropdown("pays", page: page, options: {"FR" => "France"}, x: 100, y: 550, width: 120, height: 20)
end
----
+
Le MVP s'appuie sur `/NeedAppearances true` pour les appearance
streams des champs texte / case / dropdown (le visualiseur les
régénère au remplissage). Les appearance streams custom de tous
les types arriveront en J1.

* **`doc/RATIONALE.adoc`** — document fondateur substantif de la
  trajectoire ISO PDF de ce shard sur 18-24 mois : ambition
  pragmatique (ISO 32000-1 + PDF/A-2b/3b + PDF/UA-1 + extensions
  crypto PDF 2.0), éclatement futur en quatre shards (`pdf`, `pdf-a`,
  `pdf-ua`, `pdf-validate`), cinq jalons (J1-J5), validateur déclaratif
  inspiré veraPDF. Hors scope assumé : PDF/X, PDF/E, PDF/VT.

* **`examples/acroform.cr`** — démo end-to-end qui exerce tous les
  types de champs. Génère `acroform_demo.pdf` (~8 Ko), prêt à ouvrir
  et remplir dans n'importe lequel des quatre visualiseurs majeurs.

=== Modifié

* `PDF::Document` expose `#acroform(&)` et `#acroform?`.
* `PDF::Page` expose `#add_annotation_ref` pour qu'AcroForm puisse
  attacher des références d'annotations widget pré-enregistrées à
  `/Annots` sans les ré-enregistrer.
* `Document#finalize!` finalise désormais l'AcroForm *avant* les
  pages, pour que les références widget atterrissent dans les bons
  tableaux `/Annots`. Sans cet ordre, les widgets existent comme
  objets indirects mais ne sont jamais reliés à une page.

== v0.5.6 — 2026-06-01

=== Corrigé

* **Rejet explicite des fontes OpenType/CFF (`.otf`) au chargement.**
  Avant ce fix, charger une fonte `.otf` (header sfnt `OTTO`) passait
  silencieusement, et l'erreur ne remontait qu'au moment du subsetting
  avec un message obscur `Missing required table: glyf`. Désormais
  `PDF::Fonts::TrueTypeFont.load` lève `UnsupportedFontFormat` avec
  un message actionable expliquant que seules les fontes TrueType
  (table `glyf`) sont supportées, et suggère la conversion via
  fontforge.

=== Supprimé

* Nettoyage de deux fichiers résidu dans `docs/` qui concernaient
  `crystal-asciidoctor-pdf` (et non ce shard) : `DEVELOPMENT_ROADMAP.adoc`
  et `ROADMAP_ANALYSIS.adoc`. La doc Antora active (`docs/antora.yml`
  et `docs/modules/`) est préservée.

== v0.3.6 — 2026-04-27

**Compatibilité PDF étendue : 1.5+ et streams non décodables.**
Lève le bloquant qui interdisait à `Reader` de lire les PDF
modernes générés par LilyPond, Microsoft Word, ou n'importe quel
moteur produisant des xref streams ou des images CCITT/DCT.

=== Ajouts

* **`Parser#parse_xref_stream`** (PDF 1.5+, ISO 32000-1 § 7.5.8) —
  remplace la table xref classique par un objet stream
  `/Type /XRef`. Format : `/W [w1 w2 w3]` (largeurs de champs en
  octets), `/Index` (sous-sections), entrées en gros-boutiste.
  Trois types d'entrées pris en charge :
  ** Type 0 (objet libre)
  ** Type 1 (objet en usage classique, `field2`=offset)
  ** Type 2 (objet compressé, `field2`=numéro objstm,
     `field3`=index dans le stream)
* **`Parser#resolve_compressed_object`** (PDF 1.5+, ISO 32000-1
  § 7.5.7) — lit un objet stocké dans un object stream
  (`/Type /ObjStm`). Header `/N` + `/First` + paires
  `obj_num offset_in_stream` + valeurs des objets en clair.
* **`Reader#resolve_reference`** consulte automatiquement
  `Parser#compressed_objects` quand un numéro d'objet n'a pas
  d'offset xref direct → les objets PDF 1.5+ deviennent
  transparents pour le caller.
* **`Parser` : Predictor PNG** (algorithmes None/Sub/Up/Average/Paeth)
  appliqué après FlateDecode quand `/DecodeParms /Predictor >= 10`.
  Indispensable pour les xref streams.
* **`Parser` : ASCIIHexDecode et ASCII85Decode** sont désormais
  pleinement décodés.
* **`Stream#decoded`** (`Bool`, par défaut `true`) — drapeau qui
  indique si `data` contient les octets décodés (filtres inversés)
  ou les octets bruts encodés (filtre non supporté).

=== Modifications

* **`Parser#decompress_stream`** signe désormais `Tuple(Bytes, Bool)` :
  si un filtre n'est pas inversible (CCITTFaxDecode, DCTDecode,
  JBIG2Decode, JPXDecode, LZWDecode, RunLengthDecode, Crypt), le
  parser conserve les octets ENCODÉS et marque le `Stream` comme
  non décodé. Les copieurs (mergers) DOIVENT respecter ce drapeau :
  préserver `/Filter` `/DecodeParms` à la ré-écriture quand
  `decoded == false`.

=== Suppressions

* L'avertissement bruyant
  `"AVERTISSEMENT : stream xref détecté (PDF 1.5+), non supporté en v1"`
  qui s'affichait à chaque PDF moderne. Plus d'usage : tout est lu
  silencieusement.

=== Tests

* 776 specs verts (inchangés). Validation manuelle sur un corpus
  de 16 PDF (PDF 1.3 à 1.7, scans CCITTFaxDecode, JPEG DCTDecode,
  LilyPond, MS Word, Finale, Sibelius) : tous lus correctement.

== v0.3.5 — 2026-04-26

=== Ajouts

* **`TrueTypeFont#has_glyph?(char)`** — indique si la police
  contient un glyphe pour `char` (i.e. le caractère sera rendu
  comme autre chose que le carré tofu `.notdef`). Permet aux
  appelants de construire une chaîne de fallback de polices :
  si la police primaire retourne `false`, essayer la suivante
  au lieu de laisser un tofu silencieux dans le PDF. Utilisé par
  crystal-asciidoctor-pdf v2.3.24.12+ pour piloter son sanitiseur
  WinAnsi plus finement.

== v0.3.4 — 2026-04-25

=== Corrections

* **Réouverture des PDF amendés via `add_content_stream`**.
  `PDF::Reader.open` plantait avec `Invalid Int32: ""` (levée
  depuis `find_xref_offset`) à la réouverture de tout PDF
  contenant un content stream binaire — typiquement un stream
  avec des octets ≥ 0x80, produit par `crystal-watermark`,
  `crystal-combine-pdf` et toute autre bibliothèque amont qui
  ajoute du contenu via la mise à jour incrémentale (spec PDF
  § 7.5.6).

  Cause racine : `find_xref_offset` cherchait `"startxref"` via
  `String#rindex`, qui retourne un offset en **caractères**
  (UTF-8). Dès qu'une séquence UTF-8 multi-octets apparaissait
  dans la zone de recherche (n'importe quel octet ≥ 0x80 suivi
  d'un octet de continuation), l'offset en caractères se
  désynchronisait de l'offset en octets et
  `@pos = search_start + idx + 9` tombait au-delà du vrai
  marqueur `startxref`. `read_int` lisait alors une chaîne vide
  et crashait.

  Correctif : scan direct des octets bruts via un nouvel auxiliaire
  privé `byte_rindex(haystack, needle, from)`. Aucune
  interprétation des octets en UTF-8 — la recherche est purement
  octet-à-octet et insensible à l'encodage des content streams
  voisins.

* Nouveau test de non-régression dans `spec/pdf/reader_spec.cr`
  (« réouvre un PDF amendé contenant des octets binaires
  (≥ 0x80) ») qui amende un PDF avec un content stream couvrant
  toute la plage 0..255 et vérifie que `PDF::Reader.open` retourne
  le bon nombre de pages.

== v0.3.3 — 2026-04-23

=== Ajouts

* **Cache de parseurs SVG**. `PDF::Document` met désormais en
  cache les instances `SVG::Parser` par chaîne source, ce qui
  évite de ré-exécuter le parseur XML à chaque appel quand le
  même SVG est dessiné plusieurs fois sur le même document
  (typique pour des drapeaux de pays répétés dans un tableau).
  Exposé via `Document#svg_parser_for(svg_data)`.

== v0.3.2 — 2026-04-23

=== Corrections

* **Commande `Z` des paths SVG** : `renderer.cr` utilisait
  `page.close_stroke` pour terminer un sous-chemin sur `Z`, ce qui
  émet l'opérateur PDF `s` (close + stroke). Le chemin courant
  était alors consommé et l'appel suivant à `apply_fill_and_stroke`
  n'avait plus rien à remplir. Visuellement, les formes SVG
  fermées apparaissaient comme de fins contours plutôt que comme
  des zones remplies — en particulier les drapeaux de pays
  affichaient des carrés vides au lieu de bandes de couleur. Passé
  à `page.close_path` (opérateur PDF `h`) pour que le chemin reste
  disponible pour le choix fill/stroke.

== v0.3.1 — 2026-04-23

=== Corrections

* **Tokenizer du `path_parser` SVG** : correction d'une boucle infinie
  déclenchée par certaines chaînes de commandes compactes. Quand un
  nombre se terminait par un `.` immédiatement suivi d'un autre `.`
  commençant le nombre suivant (par ex. `4.4.8` ou `3 0.5.7`, motifs
  fréquents dans les SVG compacts de drapeaux), la boucle interne de
  parsing de nombre sortait sur le même `.` qu'elle venait d'arrêter
  sans avancer `i`, et la boucle externe tournait indéfiniment à 100 %
  CPU. Le correctif fait consommer de manière inconditionnelle le
  premier caractère d'un token numérique.
* Ajout de specs `PDF::SVG::PathParser` couvrant le cas dégénéré et
  un extrait du path Brésil qui bloquait auparavant.
